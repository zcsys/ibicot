# Native integration handoff

`game/mobile/lib/native_services.dart` supplies the real Flutter purchase, secure-storage and advertising bridges. It is separate from the frozen base service evidence. `NativeServicesManager` never changes the core wallet, pass XP or local saved branch.

The default configuration is disabled. A null client leaves guest initialization free of credential, billing and advertising SDK calls. Enabling purchases attaches the existing `in_app_purchase` stream, queries actual localized products, binds the random service account ID to StoreKit `appAccountToken`/Google's obfuscated account ID, handles pending/cancelled/error states, and verifies through the service before completing a native transaction. Interrupted delivery remains retryable. Restore uses the real SDK. The ownership getter checks the current signed-in account and local main-game seed on every read. Each receipt expires from its server observation time using monotonic elapsed time; an expiry timer notifies the UI. Wrong main-game seed or unavailable service cannot authorize new ownership. This is fresh service observation caching, not a signed offline receipt cache. Before buying, the server-linked seed must match the local game; recovery acknowledgement must already be retained.

The secure store is `flutter_secure_storage` 11.2.0: iOS device-only Keychain accessibility, Android authenticated encryption/Keystore with migration backup, and macOS legacy Keychain to avoid requiring a provisioning profile for development. Session keys are bound to the service origin; privacy state also binds to account UUID. Recovery codes are never stored in preferences or gameplay. The UI must retain a newly issued code before acknowledging recovery and before first upload. Rotation takes a pre-retained new code. Storage failure must not hide an already-issued recovery result.

Privacy withdrawal disables collection immediately, preserves an account-specific pending remote deletion in secure storage, and never applies that request to another account. Remote logout/deletion success clears in-memory ownership even if local secure cleanup fails; surface `secure_session_cleanup_required` accurately. Native SDK/network behavior and device secure-storage durability remain unqualified by host tests.

Advertising is initialized only after an explicit optional ad request, real unit configuration and UMP consent availability. Sample ad unit IDs remain disabled. Native reward callbacks only trigger polling for an independently verified service receipt; no callback directly increases Support allowance. Failure/no-fill/late server callbacks leave the core free briefing route available. The host supplies `isStillEligible` to recheck the current day/slot at each asynchronous boundary. Loaded ads are disposed on timeout, changed eligibility, setup/show failure and dismissal; late loads after timeout are also disposed. The host must apply returned claims through the core's same-day/slot checks and persist before acknowledging delivery.

Author checks are in `game/mobile/test/native_services_test.dart`; they use controlled service/store/credential boundaries and real SDK types. These demonstrate orchestration, localized-price preservation and fault handling, **not** native sandbox purchases, physical Keychain/Keystore reliability, or actual consent-network behavior. Both native store/device gates remain open.

Official references: [Flutter in-app purchases](https://pub.dev/packages/in_app_purchase), [secure storage](https://pub.dev/packages/flutter_secure_storage), [AdMob Flutter consent](https://developers.google.com/admob/flutter/privacy). Current SDK source confirms `applicationUserName` maps to Apple's account token and Google's obfuscated account identifier.
