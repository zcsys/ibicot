# Tideglass v1 release contract

Implementation baseline adopted 16 October 2026. The AI delivery roles own production and integration; product scope remains the original blueprint and v1 roadmap. Work is confined to the `idle` project. Unrelated changes in the parent checkout are preserved.

## Product decisions

| Decision | Baseline |
|---|---|
| Audience | Teen and adult incremental-game players; no child-directed advertising or social features. Actual store rating is determined from the final content questionnaire. |
| Initial distribution | iOS and Android; English launch. Prepare US, UK, Canada and Australia listings as the initial English-market proposal; account owner confirms territories at submission. |
| Native support floor | Product target iOS 16 and Android 10/API 29, subject to actual SDK qualification and device results. This is a support choice, not a claim about Flutter's minimum versions. |
| Device layout | Portrait phone layout and responsive tablet layout; internal desktop window supports iteration and automation. |
| Network | Guest local play and cached content work offline. Purchases, verified ownership refresh, cloud recovery and fresh live content require their actual services. |
| Controls | Pointer/touch with large targets, keyboard focus and activation, scalable text, reduced motion, non-color signals and independent audio controls. |
| Economy | Five producers, growth 1.12, tier step 20, 0.65 prestige exponent and the specified synergies. Free automation unlocks and equal ad/free rewards remain mandatory. |
| Content | Six chapters and ending, twelve dossiers, twelve calibrations, eighteen main archive entries, 25 producer presentations, seven harbor states, complete first season and 36 cosmetics. |
| Currency accounting | Exact integer micro-R wallet/lifetime ledger; high-precision output with carried remainders. The core decision record defines rounding and boundary tests before acceptance. |
| Local entitlement authority | Imported local save/cache data never proves a paid purchase. Native receipt verification remains separate. |
| Spend/publication | No external purchase, account enrollment or public distribution has been authorized by this local implementation step. Prepare concrete choices before those actions. |

## Build qualification and acceptance

Flutter is the provisional client runtime because this v1 requires a responsive 2D interface, accessibility and native store integrations. The portable Dart economy and persistence packages remain independent of Flutter rendering. This choice is accepted for local implementation preparation, with the complete B02 native and service gates still open.

Flutter documents native [iOS](https://docs.flutter.dev/deployment/ios) and [Android](https://docs.flutter.dev/deployment/android) distribution. The official [`in_app_purchase`](https://pub.dev/packages/in_app_purchase) package and Google's [Mobile Ads Flutter integration](https://developers.google.com/admob/flutter/quick-start) provide candidate adapter paths. Documentation and compilation do not establish successful sandbox fulfillment or production service readiness.

The native proof must include builds that launch on the declared targets, real purchase/restore sandbox flows, ad no-fill/free-route behavior and cloud revision conflict evidence. A native build with test adapters only can support local iteration but cannot close M0-03 or B02.

The original 15-person comprehension study, mature D30 cohort, real 28-day seasonal cycle, native-device performance and 14-day launch coverage remain requirements. Simulator tests and accelerated time are separate engineering evidence.

## Current operating scope

The director writes integration and progression specifications; gameplay owns the portable core; client owns Flutter views/controllers; platform owns local native toolchains, platform adapters and services; art/content owns production assets and authored content; QA independently verifies behavior. At most three specialists execute alongside the director.

The first executable delivery is a correctly persisted purchase, Rechart preview, close/return and recovery flow. No additional producer, prestige layer, multiplayer system or public web-only substitute is in scope.
