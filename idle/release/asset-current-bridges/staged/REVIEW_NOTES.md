# Staged asset evidence/version bridge

This packet supplies one record for each of the **164 original asset IDs**. It is an integration proposal, not a release decision. Only this staged directory was written. The live contract, manifest, original provenance, approval fields and canonical verification paths are untouched.

`bridge.json` preserves the complete original contract and manifest record per ID, exact required variants, current source/export/provenance hashes, declared child-media hashes, registered selectors/runtime paths, prior inventory/registration identity comparisons, reviewed matrix row indices, source-version relations, and specific remaining requirements. `evidence-index.json` binds every adopted review/run to exact files and records changes since the reviewed full source snapshots. `differences.json` binds exact before/after bytes and unified patches. `criteria.json` retains the actual original acceptance and named-reviewer rules.

The inventory distinguishes **registered files supplied** from complete editorial, presentation, rights or release acceptance. A source/export existing is never reported as all variants passing. Every original per-asset canonical verification path remains absent; every current null reviewer/review-evidence field is preserved. The 37 stale contract records are proposed for `in_production` plus true file-existence flags only. Separate append-only provenance version proposals identify actual changed dependencies; the lead's already-applied, independently permitted two-page documentation-only refresh is retained as its own historical-to-current relation. This lane writes no replacement hash and fills no approval.

## Safe integration sequence

1. Independently review the frozen packet and exact proposed changes. Run `check_bridge.py --self-test`; use `--live` only to ask whether production still equals this freeze. A later source change should fail the live check, not invalidate the archived facts.
2. After the active content matrix finishes and is independently reviewed, append that result at its exact source/report hashes. Keep failed and intermediate StoryScreen runs separate. Reconcile any further source changes explicitly before integrating metadata.
3. Apply only the reviewed existence/version metadata changes. Preserve old provenance records/capture pins and all existing null approval fields. Reviewers may then create bounded, attributable new review entries; this author packet is not their acknowledgement.
4. Resolve full original per-asset/rights/native/operator/calendar criteria through their actual owners before any canonical `verified`, content gate or whole-package acceptance.

No Flutter/native tool, browser session, asset regeneration, provider account, publication or external procurement was used for this bridge. Read-only comparison and Python validator execution are its author checks; a different reviewer remains required for integration.
