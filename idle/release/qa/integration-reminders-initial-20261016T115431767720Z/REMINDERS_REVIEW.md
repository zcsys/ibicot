# Independent reminder integration review

The pinned reminder implementation passes 30 host tests: 17 author cases, five director integration cases and eight new independent cases. Focused analysis of eight files is clean. No actionable defect was reproduced. This qualifies the reviewed host behavior only; M3-05 and M5-02 remain in progress.

Source was captured on 2026-10-16 before the interruption. On completion of this record, all 303 frozen input hashes and the supplemental independent test hash were reverified. The fingerprint is `88bf971fc5ffa7898178e6a7e03552c5222ef46280b4ccf7688ee46486577d6d`. The historical successful logs are preserved unchanged. This report does not present those logs as a fresh run of subsequent production edits. `snapshot.json` records source copies and the exact app/bootstrap/controller call-site hashes; `verification.json` records test counts and scope limits.

The independent tests exercise duplicate background requests followed by return during a delayed save; actual 120-hour offline replay followed by a durable-save-before-schedule check; duplicate return/resume during replay; opt-out while scheduling is in flight; cancellation after a partial native failure and subsequent recovery; timezone replacement; and preservation of an already committed absence plan when the lifecycle closes. A further case checks 384 departures across UTC, Istanbul, New York and Lord Howe on daylight-saving transition dates. Each plan is bounded to three unique IDs, outside the configured local quiet hours, no earlier than economic readiness, and inside the 72-hour planning horizon. These are controlled virtual time tests, not elapsed-day observations.

Source review confirms default-off preferences, permission requests only after explicit enablement, separate bounded preference storage, cancellation limited to the three owned notification IDs, serialized operations and no economic mutation by the planner. ReminderLifecycle waits for replay and a successful durable save, rejects stale generations after a return/close, and preserves legitimate scheduled absence reminders when the UI closes. The pinned app suspends on inactive without scheduling; paused/detached runs the persistence path; return cancels. Startup initialization does not request permission.

The settings surface supports per-category controls, quiet hours and OS notification settings, with a 320-pixel/200%-text expanded-copy test. The native adapter initializes iOS without prompting and requests quiet, inexact one-shot reminders; Android has POST_NOTIFICATIONS and a non-exported scheduled receiver, without exact-alarm or boot-rescheduling privileges. The adapter tests inspect mocked plugin method arguments. They do not establish actual OS permission presentation or delivery.

Actual iOS/Android delivery, revocation, suspension, battery behavior, physical accessibility and device compatibility remain unqualified. The OS may delay or suppress an inexact request. A timezone change while the application is terminated is not observed until return; displayed copy states the scheduling timezone basis. Android reboot rescheduling is absent. Closing after a valid committed absence plan intentionally preserves that plan; this review does not assert that disposal prevents every queued plugin operation. Moving localization, unrelated numeric/simulation changes and the final native candidate are excluded.
