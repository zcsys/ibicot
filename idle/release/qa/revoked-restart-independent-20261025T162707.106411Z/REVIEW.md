## Behavior and gate preservation

The new Android-only preparation is deliberately not a passing integration test. It creates a fresh isolated fixture, observes the original default-off state and real allowed opt-in, uses the production save/lifecycle/scheduling path, then flushes a checkpoint before the actual Settings OFF action. The host exports the checkpoint, preference and save bytes while the exact PID is alive and package-bound; the operator must wait for the explicit host capture line. The host validates a fresh exact-PID reason-8 `PERMISSION CHANGE` / `PermissionHelper` exit, actual denied package state, unchanged durable files, and expected driver disappearance. Unrelated framework failures remain failures. Its status is an interrupted handoff with `passed=false`, not a native pass; exit zero for that handoff cannot be interpreted as full acceptance.

Recovery requires that exact new interrupted preparation, the same candidate/harness/tools/device/label/pair identity, archived source and raw checkpoint hashes, and the actual operator packet. It requires observed ON→OFF XML, raw PNGs, bound Settings package/process route, a tap inside the observed switch, and action times enclosing the exact OS kill. The PNG signature check is only structural; future independent visual inspection remains required. A stale old failed `revoked` report cannot satisfy these gates.

The fresh recovery process must have a different actual PID, retained checkpoint/save/preferences, and actual denied permission before initialization. It invokes real production initialization, records pending/active IDs both before and afterward, and requires no remaining IDs afterward. Recording the before state avoids attributing OS-cleared notifications to production cancellation. It verifies the retained snapshot/payload/cursor, exercises the production denied scheduling and return paths, and performs explicit denied re-opt-in that persists enabled=false. Save generations and the checkpoint must remain unchanged. A remembered enabled=true preference on initialization is current production behavior, distinct from effective permission; the test preserves that distinction instead of manufacturing a fresh default.

Original framework/driver success, negative-log detection, source/frozen-production checks and artifact binding still apply to recovery. The original five scenarios' Dart implementation is byte-identical after removing only the two new branches/helpers. Independent AST comparison also found the original runner's payload validator, departure/return verifier, source/artifact functions, device readiness and final observation code unchanged. The separate semantics finding requires only the prospective operator observation refinement; this stage adds no handle disposal or assertion suppression.
