## What was exercised

The harbor cases mount the real `TideglassApp`, assert each actual restoration selector and image semantics, and observe phase changes/stops under the requested motion setting. Producer cases use the real purchase cards, renderer tier/stage, displayed name, available purchase callback, actionable semantics and at least 48×48 logical-pixel button bounds. Initially locked tiers show a lock icon and requirement text and expose no purchase button.

Every cosmetic uses the actual collection card, full preview dialog and equipped app harbor. The same ID moves through locked → owned → equipped. Purchase callbacks do not grant ownership. Free-pass ownership uses the actual reward claim; chapter/decoration ownership is seeded and normalized through the public controller before comparison; paid ownership is an explicitly synthetic verifier fixture. The entire economic JSON, including revision and daily state, remains equal through presentation and tested equip/remove/re-equip actions. Actual harbor, five producer-card and first purchase-button rectangles remain identical when the item is removed and re-equipped. Ownership/equipped states have text equivalents; control labels and preview image semantics are checked.

The 160-pixel thumbnail uses the real `CosmeticPreview` in a labeled component scaffold. The extra 600 selected/locked producer combinations per mode use the real renderer in labeled component scaffolds. These are not invented product routes: high-stage locked saves, a producer-selection route and a separate 160-pixel thumbnail route are not claimed as reachable gameplay. The initial valid lock checks cover four actually unavailable tiers per display condition. No new unchanged-art screenshots or placeholder media were generated to inflate coverage.

Both full runs also check representative actual-app pause/resume, OS reduced motion, unchanged economic state at a fixed clock, and zero retained animation callbacks after unmounting. Sixteen declared text/background color pairs, including the actual build-button composite, exceed 4.5:1; the lowest is muted text on raised background at approximately 6.277:1. This palette calculation is not a complete text/non-text contrast audit, pixel inspection, screen-reader qualification or WCAG certification. Decorative/disabled exceptions and remaining contrast coverage are described in `source/art/verification/coverage-contract.md`.

## Failure history and repairs

All failed runs remain preserved. Earlier author-test failures were deprecated semantics API usage, late semantics-handle disposal, wallets seeded without matching lifetime income, a paid offer incorrectly constructed for a free item, and a chapter fixture whose daily discovery availability had not been normalized before comparison. One early sample also had concurrent core edits and is explicitly rejected as a consistent-source result. These led to test-fixture/API repairs; no production defect was established or runtime file changed in this work.

The chapter repair uses the real public `equipCosmetic(null)` coordinator path before capturing the owned baseline, then repeats it and requires full-state idempotence. It does not remove daily/revision fields or loosen the later economic equality assertion. Full chronology, exact failed-proof paths and staged locale extension are retained in `source/art/verification/AUTHOR_STATUS.md` and `staged-pseudo/`.
